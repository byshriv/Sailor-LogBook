# Phase 1 technical review and decision record

The owner requested completion and delegated technical choices on 28 October 2026.
This is an implementation/design review, not an independent security audit or an invented
owner visual sign-off. Large Calendar/product-flow changes still need owner review later.

## Decisions resolved

- Keep the selected React/TypeScript/Redux/Vite stack and isolated package directions.
  The atomic durability/replay spike passes; complete causal clocks/checkpoints remain Phase 2.
- Do not vendor Super Productivity's whole app or incomplete source cache. Its @sp packages
  are unavailable to this session in npm. Implement our narrow sync/provider integration
  behind the reviewed ports; retain the pinned review as architectural evidence. Use vetted
  primitives from public pinned packages rather than copying an unbuilt crypto subset.
- Select hash-wasm 4.12.0 (MIT) for the Argon2id feasibility candidate and WebCrypto AES-GCM.
  Candidate KDF: 19,456 KiB, two iterations, one lane, 32-byte output and random 16-byte salt.
  This is the OWASP Argon2id minimum candidate, not a measured universal phone budget or an
  enabled production format. Node/browser correctness and WASM loading are tested separately.
  Real-device memory/latency tuning remains a Phase 9/11 release gate.
- Finalize v8 cutover/rollback behavior in migrations/V8-CUTOVER-CONTRACT.md. New production
  transport never overwrites the legacy demo file. Returning old edits use explicit recovery/
  merge review. No claimed remote erasure of offline copies.
- Keep the master-key/independent passphrase/recovery-wrapper design in ADR 0003. Serialized
  production format must bind logbook ID, key generation, wrapper role and KDF parameters as
  authenticated context; reject unknown versions and non-allowlisted resource parameters.
  Recovery file/code need version/checksum and verify-before-enable. No plaintext fallback.
- Native host uses proof-only work.shriv.sailorlogbook.proof, Android 12/API31 minimum,
  Capacitor core/android 8.5.3. CLI 8.4.3 avoids a moderate-advisory xcode/uuid chain introduced
  by CLI 8.5.x; cap sync was rechecked with the earlier compatible CLI. Production app ID and
  release signing remain Phase 10 choices, never derived from this disposable proof ID.
- Hosted PR jobs build web/native artifacts without signing/deployment secrets. Repository
  admin switches must be enabled by the owner because the connector has no admin mutation
  tools. The owner chose exact-setting instructions; this gate is not silently waived.

## Encryption activation/rotation acceptance contract

New unencrypted sync precedes optional setup. Encrypted content includes attachments and
all journal fields. Persist encryption-required policy separately from key availability.
Enable/change encryption only after current transfer quiesces, source recovery and verified
unlock/recovery, then a revision-checked complete generation commit. Interrupted generation
uploads remain unreferenced and cannot be applied as a partial logbook.

Passphrase or recovery-secret changes verify the new wrapper before committing it. Changing
a wrapper alone cannot revoke old copies of ciphertext/key material. Lost-device handling
requires new content keys, re-encryption, generation barriers and provider-token revocation
where appropriate; prior plaintext revisions and offline local copies remain outside a
promise of retroactive confidentiality. Explicit Lock clears session keys and personal
widget projections. Production rotation/native trust tests remain Phase 9/10 gates.

## Remaining release evidence

Physical Android/Safari/macOS/Linux coverage, OS unlock/reboot/Keystore behavior, drawing/
photo performance and independent encryption review cannot be inferred from CI/emulation.
Record actual versions/results during the relevant product phases. The Phase 1 emulator
checks, when green, establish bridge feasibility only. No production deployment is enabled.
